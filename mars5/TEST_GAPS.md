# Test Gaps — MARS MIPS Simulator

**Status:** Living document. Add new gaps whenever they are discovered during Phase 2 refactoring.  
**Purpose:** Unit-test backlog. Every row here is technical debt that must be addressed before the corresponding Phase 2 subsystem is considered complete.

---

## High-priority gaps (Phase 2 blockers)

| Area                 | What is uncovered                                                                                   | Why it matters                                                                                                                                        | Suggested test type                                                                                                               |
|----------------------|-----------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| `BasicInstruction`   | Per-instruction encoding mask correctness for all 155 basic instructions                            | An incorrect mask silently produces wrong machine code; characterization tests only verify assembly completes, not binary output                      | Parameterized unit — given operand values, assert the correct 32-bit encoding                                                     |
| `BasicInstruction`   | Simulation semantics for each of the 155 basic instructions                                         | A wrong simulator action (wrong register written, wrong value) is invisible unless explicitly verified                                                | Parameterized unit — set up register/memory state, execute one instruction, assert resulting state                                |
| `Memory`             | All boundary addresses per `MemoryConfiguration` (text limit, stack limit, kernel data limit, etc.) | Off-by-one at a limit silently allows or rejects valid addresses                                                                                      | Unit — try address at boundary ± 1 for each of the 21 named addresses                                                             |
| `Memory`             | Unaligned halfword access at every offset within a word                                             | MIPS raises an address exception for unaligned access; any regression in the check would silently corrupt data                                        | Unit with exception assertions                                                                                                    |
| `Memory`             | Segment overlap edge cases (addresses at exact segment boundaries)                                  | A gap or overlap between segments causes silent memory aliasing                                                                                       | Unit with adjacent-address reads/writes                                                                                           |
| `Assembler`          | Macro expansion — `.macro`/`.end_macro` with multiple call sites                                    | Macros are expanded at tokenize time; a regression in expansion produces wrong instruction sequences                                                  | Integration — assemble a program with a macro called N times, verify machine list length and content                              |
| `Assembler`          | `.eqv` and `.set` constant substitution                                                             | These are pre-processor substitutions; a regression changes the assembled constant value                                                              | Unit — assemble with `.eqv X, 42`, use X in an instruction, verify binary                                                         |
| `Assembler`          | Forward-reference resolution — label used before defined                                            | The second pass must resolve all forward refs; missing one produces a zero-address branch or jump                                                     | Integration — program with forward branch, verify target address                                                                  |
| `Assembler`          | Error message content and line number accuracy                                                      | Error messages are user-facing; wrong line numbers make debugging hard                                                                                | Unit — assemble an intentionally invalid program, assert message text and line                                                    |
| `PseudoInstructions` | Each extended instruction's expansion — verify the generated basic instruction sequence             | A wrong expansion produces silently incorrect behavior; only the final result (not the expansion) is currently verified                               | Unit per pseudo-instruction — assemble a single pseudo-instruction, inspect the machine list for exact basic-instruction sequence |
| `BackStepper`        | Undo correctness after every instruction class that modifies state                                  | The back-stepper maintains a history stack; a regression causes the wrong state to be restored                                                        | Integration — execute N instructions forward, step back N times, assert state equals initial state                                |
| `Coprocessor1`       | IEEE 754 edge cases: NaN, ±Inf, denormal inputs to all FP instructions                              | MIPS FP semantics are precise about NaN propagation and exception flags; any divergence causes subtle scientific computing bugs                       | Unit per FP instruction with edge-case inputs                                                                                     |
| `Coprocessor1`       | Rounding mode behavior (round-to-nearest, round-toward-zero, etc.)                                  | Programs relying on specific rounding modes would produce wrong results if the mode is ignored                                                        | Unit — set FCSR rounding mode, execute a rounding instruction, verify result matches expected rounding                            |
| `Syscalls`           | All 45 syscall behaviors against a headless `SyscallEnvironment` stub                               | Current tests only cover syscalls 1, 4, 10, 11, 34 via simulation; file I/O (13–16), open/close (13–16), sbrk (9), and others are completely untested | Integration with mock environment                                                                                                 |
| `SymbolTable`        | Duplicate label detection (same label defined twice in same scope)                                  | The assembler should report an error; a regression silently picks one definition                                                                      | Unit — assemble program with duplicate label, assert error message                                                                |
| `SymbolTable`        | Global vs local scope (`.globl` label visible across files, local label not)                        | Cross-file visibility is critical for multi-file programs; a regression causes wrong address resolution                                               | Integration — two-file assembly, verify cross-file label resolved and local label not                                             |
| `SymbolTable`        | Forward references through multiple files in a multi-file assembly                                  | Forward refs that span file boundaries are resolved in the second pass; a missing resolution causes a zero-address                                    | Integration — multi-file program with cross-file forward reference                                                                |
| `Tokenizer`          | All comment styles (`#` to end of line)                                                             | A tokenizer regression on comments could cause valid programs to fail assembly                                                                        | Unit — programs with comments in various positions                                                                                |
| `Tokenizer`          | String/char escape sequences (`\n`, `\t`, `\\`, `\"`, `\0`)                                         | Wrong escape handling produces wrong string content in memory                                                                                         | Unit — `.asciiz "a\nb"`, verify byte content in memory                                                                            |
| `Tokenizer`          | Edge-case integer literals: hex (`0xDEAD`), octal (`0777`), negative, max-int, min-int              | Overflow or sign errors in literal parsing produce wrong immediate values silently                                                                    | Parameterized unit — verify each literal format produces the expected int value                                                   |

## Gaps found during characterization test writing (2026-05-03)

- **`SyscallLoader` had wrong package constants** (`mars.*` instead of `edu.missouristate.mars.*`) after the package rename. Fixed in Phase 1. Added to the watch list for any future package changes.
- **`Memory` uses little-endian byte ordering** (byte at the lowest address is LSB of word). This is counter to SPIM's default big-endian. Pinned in `MemoryTest.dataSegment_bytesComposeWord`. Should be explicitly documented in the Phase 2 Memory refactoring.
- **`BasicInstruction` list contains 16 deliberate mnemonic duplicates** (R-type and I-type trap instruction pairs). Pinned in `InstructionSetTest.knownDuplicateMnemonicsAreStable`. These should be handled explicitly in the Phase 2 data-driven instruction definitions.
- **No branch/loop/recursion/FP test programs** in the current test corpus. The 15 existing programs exercise only linear control flow. At minimum 3–5 programs covering conditional branches, loops, and stack-based recursion are needed before Phase 2 begins.
